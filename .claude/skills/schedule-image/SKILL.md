# 일정 이미지 → games.json

이미지 판독은 직접 하고, 검증·중복 제거·정렬·저장은 `scripts/import_schedule.py` 에 맡긴다.
games.json 을 손으로 편집하지 않는다 — 매일 도는 자동 갱신(`update_data.py`)과 필드 규약이 어긋난다.

## 절차

1. **게임 식별.** 이미지에 게임명이 없는 경우가 많다. 고유명사(캐릭터·지역·재화 이름)를 웹 검색해 확정한다.
   추측으로 넘어가지 말 것. 확정되면 `data/games.json` 에 이미 있는 id 인지 확인한다.
2. **행 단위로 판독.** 막대 하나 = 엔트리 하나. 막대 위 라벨(`9.16-10.28`)이 일차 근거이고,
   라벨이 없으면 상단 날짜 눈금에서 읽는다. **이미지에 없는 일정은 만들지 않는다.**
3. **스테이징 JSON 작성** — 스크래치패드에 쓴다. 형식은 `scripts/import_schedule.py` 상단 docstring 참조.
4. **`--dry-run` 으로 확인** 후 실제 병합:
   ```bash
   python3 scripts/import_schedule.py /path/to/staging.json --dry-run
   python3 scripts/import_schedule.py /path/to/staging.json
   ```
5. **결과 보고.** 판독이 애매했던 항목(연도 추정, 종료일 미표기 등)을 사용자에게 명시한다.
   커밋·푸시는 사용자가 요청할 때만 한다.

## 판독 규칙

- **날짜는 KST.** 이미지에는 연도가 없다. 버전 시작일과 오늘 날짜로 연도를 정하고,
  `12.28 → 1.5` 처럼 해를 넘기면 끝 날짜만 +1년 한다.
- **타입 매핑**
  | 이미지의 줄 | `type` |
  | --- | --- |
  | 버전/업데이트 기간 | `version` |
  | 픽업·확률 UP·가챠·포획 UP 로테이션 | `banner` |
  | 그 외 전부 (스토리, 로그인, 재화 부스트, 상시) | `event` |
- **같은 이벤트가 여러 번 반복**되면 엔트리를 나누고 `subtitle` 에 `1회차`, `2회차` … 를 넣는다.
  같은 `title` + 같은 `start` 조합은 스크립트가 거부한다.
- **종료일이 안 보이는 상시 이벤트**는 `tentative: true` 를 붙이고, 차트에 그려진 범위의 끝까지로 둔다.
- **카테고리 접두어**는 title 에 합친다 — `풍요로운 지맥 - 천휘 설휘랑`. 이미지의 세로 카테고리 라벨은
  타임라인에 따로 렌더링되지 않는다.
- `version` 필드에는 해당 버전 번호를 넣는다. 모르면 빈 문자열.
- `source` 는 공식 사이트 도메인 또는 이미지 출처를 적는다 (예: `aniimo.com 공식 일정`).
- 미확정(점선·"예정" 표기)은 `tentative: true`.

## 새 게임일 때 추가로

`game` 블록을 채운다. `id`(영문 소문자), `name`(한국어), `fullName`, `color`(다른 게임과 겹치지 않는 hex),
`icon`(이모지), `developer`, `iconUrl`(공식 사이트 파비콘 — `curl -sI` 로 200 확인). 예시는 `data/games.json` 참고.

## 주의

- 임포트한 항목에는 `_auto` 를 붙이지 않는다. 붙이면 자동 갱신이 90일 뒤 지워버린다.
- 반영 후 `git pull --rebase` 가 필요할 수 있다. CI(`update-data.yml`)가 매일 같은 파일을 커밋한다.
